# PRD：笔灵（Biling）· AI 小说写作伙伴

> 版本：v0.1（草案）｜日期：2026-09-10｜状态：待评审

---

## 1. 项目概述

### 1.0 产品名

**笔灵（Biling）**——"笔下有灵"。

### 1.1 定位

一个**能记住你的世界、理解你的角色、随故事推进而成长的 AI 写作伙伴**。它不是"输入关键词自动出小说的生成器"，而是一套**围绕单一小说项目组织的协作工作区**：AI 扮演多个分工角色，配合作者完成从"脑洞"到"完稿"的全过程。

### 1.2 一句话描述

把"概念引导、蓝图设计、大纲编排、章节写作、记忆压缩、质量评价"拆成 6 个可协作的 AI 角色，配合**共享记忆层**与**用户风格学习**，做作者真正的长期写作搭子。

### 1.3 与"自动生成器"的本质区别

| 维度 | 自动生成器 | 本产品 |
|---|---|---|
| 是否记得设定 | 每次重新灌 prompt | 有持久化设定库，按相关性检索 |
| 是否一致 | 前后容易矛盾 | 伏笔账本 + 故事状态机兜底 |
| 是否贴合作者 | 固定风格 | 从用户编辑 diff 中学习风格画像 |
| 是否可复盘 | 不能 | 蓝图/大纲/章节全版本化，可对比 |
| 是否参与创作决策 | 一把梭 | 每个角色产出都需作者审阅/确认 |

## 2. 用户画像与核心场景

- **网文/长篇小说作者**：写了几十万字后设定前后矛盾、剧情线失控 → 需要设定集中管理与伏笔追踪。
- **创作新手/灵感碎片多的人**：有很多脑洞但理不清主线 → 需要设定师引导、蓝图师整理。
- **卡文/状态不佳的作者**：需要"先出草稿再改"或"续写找感觉" → 需要小说家生成定稿。
- **对文笔有要求、想训练 AI 贴合自己**：需要风格画像与用户编辑校准。

核心场景：
1. 在设定管理里录入/整理设定，AI 提供冲突预检与补全建议。
2. 蓝图师把设定整理成含主题、冲突、角色弧光、伏笔计划的完整蓝图。
3. 大纲师按蓝图逐章产出大纲，同时登记伏笔账本。
4. 小说家基于"检索到的相关设定 + 本章大纲 + 压缩记忆 + 风格画像"一次产出定稿正文。
5. 作者直接编辑定稿，或按评价师意见对问题段落定向修订；评价师对照蓝图与账本打分。
6. 提取师把成稿章节压缩为结构化记忆，长篇小说持续推进不崩。

## 3. 功能需求

### 3.1 设定管理（Worldbuilding Hub）

- **设定类型**：角色、地点、派系、世界观规则、物品、设定概念。
- **结构化字段**：角色（外貌/性格/目标/关系）、地点（地理/氛围/归属）、派系（目标/立场/成员）、规则（约束/代价/限制）。
- **集中查阅**：卡片视图 + 全文检索 + 语义检索（"主角喜欢吃什么"→ 命中相关设定）。
- **冲突校验**：新增/修改设定时，AI 提示与既有设定的冲突。
- **版本记录**：设定可追溯修改历史。

### 3.2 大纲与故事线（Outline & Storyline）

- **蓝图（Blueprint）**：主题、核心冲突、世界观规则、角色弧光、分卷结构、伏笔计划。蓝图**版本化**，可切换当前生效版本。
- **章节大纲（Outline）**：目标、节拍（beats）、视角、出场角色/地点、冲突、本埋伏笔、本回收伏笔、线程状态更新。
- **伏笔账本（Plot Ledger）**：可视化所有已埋未收的钩子，防止"埋了不收、前后矛盾"。

### 3.3 写作辅助（Writing Assistant）

- **先出草稿再改**：作者给提示/只给方向，AI 出草稿，作者在编辑器内修改。
- **续写找灵感**：作者写完开头，AI 续写。
- **修订**：评价师发现问题后，AI 按问题清单定向修订。
- 写作过程中右侧面板实时展示"本章用到的相关设定 / 记忆摘要 / 待回收伏笔"，AI 生成时即装配这些上下文。

### 3.4 章节生成与定稿（单版本）

- 小说家一次产出 **1 段定稿正文**（装配设定/记忆/风格上下文，SSE 流式输出）。
- 生成结果直接落为正式章节（`chapter_versions` 存档，历史版本可回看/回滚）。
- 用户可直接在编辑器修改正文，修改 diff 作为**风格学习**输入。
- 评价师对定稿对照蓝图/账本打分，问题项触发"定向修订"（小说家带 issue 清单重写特定段落）。

### 3.5 多角色协作流程

```
作者 ──▶ 设定师/蓝图师 ──蓝图──▶ 大纲师 ──章节大纲+账本──▶ 小说家(定稿) ──▶ 评价师
                                    │
        ▲──────────────── 共享记忆层 ◀───────────────────────┘
        │            （设定库|故事状态|伏笔账本|风格画像|质量账本）
        └──────────── 用户编辑/选择 ──▶ 风格学习
```

每个角色的职责、输入、产出详见技术设计文档（docs/technical-design.md）。

## 4. 核心机制需求（"不做挂羊头"的验收标准）

1. **结构化产出**：6 个角色的输出都必须符合各自的 JSON Schema，schema 校验失败自动修正后入库；禁止"输出一段话拉倒"。
2. **共享记忆层**：设定库、故事状态、伏笔账本、风格画像、质量账本五类记忆持久化，所有角色读写同一份。
3. **相关性上下文装配**：小说家收到的是"检索到的相关设定 + 压缩记忆 + 风格画像"，而不是整库灌入。
4. **伏笔闭环**：大纲师生成下一章前必须读伏笔账本，安排回收；账本可被查询"未回收钩子"。
5. **风格学习**：用户对 AI 成稿的手动修改 → diff 分析 → 更新风格画像 → 下一章体现变化。
6. **质量可复盘**：评价师打分必须附 evidence（引用原文/对照账本条目），问题可追溯。
7. **模型可切换**：换模型/换供应商只改配置，不改代码（LiteLLM 网关）。

## 5. MVP 范围与迭代路线

### 5.1 MVP（第一版可跑通的最小闭环）

- 小说项目管理、设定库（角色/地点/派系/规则 CRUD + 检索）。
- 小说家（单章节续写，产出定稿正文）。
- 提取师（成稿自动压缩为记忆，落地伏笔账本雏形）。
- 模型网关：DeepSeek/Qwen 可切换，SSE 流式输出。

> MVP 的目标：验证两个核心假设——"续写质量 + 生成时确实用上了设定/记忆/风格"，以及"长篇连续写 N 章是否前后一致"。

### 5.2 v0.2

- 大纲师（按蓝图产出章节大纲 + 伏笔账本正式化）。
- 评价师（对照蓝图/账本打分 + 修订建议 + 定向修订）。

### 5.3 v0.3

- 蓝图师（脑洞 → 版本化蓝图 + 冲突校验）。
- 风格画像上线（从编辑 diff 学习）。

### 5.4 远期

- 设定实体图谱可视化、记忆审查（长文二次摘要）、协同写作、本地模型（Ollama）支持、移动端。

## 6. 非功能需求

- **流式输出**：所有 AI 生成（大纲/章节/评价/概念）均 SSE 流式，避免长等待。
- **成本控制**：创作类用强模型，设定/提取/评价类用性价比模型；按项目隔离缓存。
- **数据安全**：小说正文为作者私有内容，API Key 加密存储，前端不暴露。
- **可观测**：每个角色调用记录输入上下文大小、token 用量、耗时，便于调优。
- **性能**：编辑器输入流畅（TipTap），长章节（数万字）不卡顿，按需分段渲染。
- **可移植**：模型供应商全可切换；数据库可选 SQLite（单机）/ PostgreSQL（部署）。
