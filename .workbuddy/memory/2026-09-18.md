# 2026-09-18

## 追查「第 2 章正文漏写兴趣爱好」：写作侧的吃设定根因

用户反馈：第 2 章系统面板只写了「天赋清单 + 适配推荐」，漏了「兴趣爱好」，而评价师也没评出来。
昨天修的是评价侧（critic + setting_checker），今天查写作侧为什么就没写进去。

### 事实核查（比用户以为的更严重）
 novelist 自己写的三章里，**两章漏同一个字段**：

| 版本 | 天赋清单 | 兴趣爱好 | 适配推荐 |
|---|---|---|---|
| 第1章 v1 (novelist) | Y | Y | Y |
| 第2章 v1 (novelist) | Y | **N** | Y |
| 第3章 v1 (novelist) | Y | **N** | Y |
| 第3章 v2 (reviser)  | Y | Y（被修订师补回） | Y |

第 3 章只是运气好走了修订才被救回来；第 2 章没人改所以一直缺。

### 三个根因（叠加）
1. **`format_blueprint_for_prompt` 静默丢数据**：只拼 `world_rule` 的 `name + detail`，
   `constraints`（本例 14 条硬规则）**从未进入任何 Agent**。蓝图文本 3986 → 修复后 4369。
2. **结构化规则被压成散文 + 埋在中段**：那条要求藏在 288 字的 `detail` 长句里，
   位于蓝图全文 **81%** 处，中间位置 + 长段落 = needle in haystack，模型注意不到。
3. **没有任何写后自检**：novelist 写完即交卷，只有评价阶段才有核对（且昨天才加）。

### 改动
- `context.py::format_blueprint_for_prompt`：world_rule 带上 `constraints`（「。硬性约束：…」拼接）。
- `setting_checker.py`：拆出 `extract_checklist()`（只抽清单，不做共现判断）+
  `format_required_list()`（写前注入文案）；`check_chapter()` 改为复用前者。
- `novelist.py` / `reviser.py`：把必现清单注入 **user_content 最末尾**（末位注意力最高，
  实测从 81% → 1%）。reviser 也要注入，因为它在重写段落时同样会删掉成组字段。
- `pipeline.py::_check_setting_gaps` + SSE `setting_warning` 事件：`novelist`/`reviser`
  产出后做同样的确定性核对，命中即下发告警。
- 前端：`api.ts` 加 `SettingGap` 类型与 `setting_warning` 事件名；`writing-panel.tsx` 用
  `settingGaps` state 接住，在「①写新的一章」卡底部渲染琥珀色告警条（生成与修订两条链路都接）。

### 踩坑
- **pipeline 有两条并行的流**：多版本 `run_agent_stream`（`versions` 数组）与单版本流
  （`{"action":"dry_run","data":{...}}`）。真实生成走的是**单版本**那条，一开始改错了地方，
  导致 mock 验证时收不到 setting_warning；靠比较 stored 事件的数据结构才定位到。
- 苍 suite：**uvicorn `--reload` 不可尽信**，验证前务必确认进程加载了新代码（必要时重启）。
- 解析 SSE 时注意格式：`event: xxx` 与 `data: {...}` 是**两行**，不是 data 里嵌 event 字段。
- Windows 的 `timeout.exe` 会盖住 GNU coreutils 的 timeout，别在 Git Bash 里用 `timeout`。
- dry_run 不落库，可放心用于端到端验证；验证完记得核对数据库行数确认无污染。
- 本地探针一律 `curl --noproxy '*'`：curl 默认走代理，后端没起来时返回的是 **502 而不是连不上**。

## 写作页 UI 微调（第 6 轮：间距 / 提取高亮 / 弹窗遮挡与取消）

1. **章节目录卷间距**：每个卷 `<section>` 的 `mb-4` 改为——最后一个渲染的卷 `mb-0`、其余卷 `mb-2`（减半）。
   做法是先 `volGroups` 过滤出"有可见章节"的组、带索引 map，按 `idx===arr.length-1` 决定 margin。
2. **「提取→记忆层」版本不一致高亮**：新增 `extractedChapterNo` + `extractedVersionId` 两个 state，
   `handleExtract` 成功时在 `stored` 事件里记录"提取的是哪一章的哪个版本 id"。
   `extractStale = 已记录且同章 && 当前激活版本 id ≠ 提取时的版本 id` → 按钮变琥珀色高亮（带 hover 边框），
   title 提示"当前正文与记忆层记录不一致，建议重新提取"；切回一致版本时 `extractStale` 自动 false 恢复。
   按章节隔离：切到其他章不会把上一章的提取状态误带过来。
3. **新增章节弹窗去滚动条**：内容容器 `gap-4 → gap-3`；「本章大纲目标」`AutoTextarea` 的 `maxHeight`
   从默认 320 降到 200（超长自动填大纲时收住高度，不撑出弹窗）。典型屏幕下整体不再触发弹窗内滚动。
4. **InfoTip 遮挡修复（根因）**：弹窗内容区是 `overflow-y-auto`，把绝对定位的悬浮解释层裁掉了 → 看不见。
   给 `InfoTip` 加 `portal` 能力：`portal` 时经 `createPortal` 渲染到 `document.body`、用 `getBoundingClientRect`
   算 `position:fixed` 定位（zIndex 200 高于弹窗 100）。写作模式 / 信息控制两处 InfoTip 已加 `portal`。
   `InfoTip` 改用 JS hover/focus 驱动（替代原 CSS `group-hover`），更稳且可 portal。
5. **信息控制弹窗：取消 + 清空只清本地**：原先直接绑全局 `form`（清空立即生效）。现新增 `infoDraft` 本地草稿，
   `openInfoModal` 打开时从 `form` 拷入；四个输入框绑 `infoDraft`。footer 三段：
   「取消」→ 丢弃草稿直接关；「清空」→ 只清 `infoDraft`（不提交）；「完成」→ `setForm({...form, ...infoDraft})` 提交后关。
   故"清空后取消"原内容仍在，"清空后完成"才真正清空。
- 验证：`tsc --noEmit` 0 错误。
- 注意：InfoTip `portal` 默认 false，弹窗外用（如提取按钮）保持原 inline 行为不受影响。
